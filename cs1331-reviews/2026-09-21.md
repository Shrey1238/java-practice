## 2. Today's concepts — writing your own classes

Until now you've *used* classes (`String`, `Scanner`, `Random`). Today you *write* them. This is the heart of the course — everything from here on builds on it.

### A. Class = blueprint, object = instance (9.1–9.3)

```java
public class Circle {
    // instance data (fields / instance variables) — each object gets its own copy
    private double radius;

    // constructor — same name as class, no return type; runs when you say `new`
    public Circle(double radius) {
        this.radius = radius;
    }

    // instance methods — operate on THIS object's data
    public double getArea() {
        return Math.PI * radius * radius;
    }
}

Circle c1 = new Circle(2.0);       // c1 is a REFERENCE to a new Circle object on the heap
Circle c2 = new Circle(5.0);
System.out.println(c1.getArea());  // call an instance method on an object with the dot operator
```

- **Reference vs. object:** `Circle c;` declares a reference (initially `null` for fields; unassigned for locals). `new Circle(...)` creates the object. Two references may point to one object (aliasing, same as arrays).
- `c1 == c2` compares references; content comparison needs a method (you'll write `equals` in October).
- A class with `main` is just a class that also has an entry point.

### B. Instance vs. static (9.5, preview of 9.7)

| | instance | static |
|---|---|---|
| belongs to | each object | the class (one copy total) |
| access | `obj.field` / `obj.method()` | `ClassName.field` / `ClassName.method()` |
| can use `this`? | yes | **no** — there is no "this" object |
| example | `radius`, `getArea()` | `Math.sqrt`, `main` |

Instance methods can access static members; static methods **cannot** access instance members directly (classic compile error: *"non-static variable cannot be referenced from a static context"*).

### C. Overloading (6.8) applied to classes

Same method name, **different parameter list** (number, types, or order). Return type alone is *not* enough.

```java
public void scale(double factor) { radius *= factor; }
public void scale(double fx, double fy) { ... }   // ok
// public int scale(double factor) { ... }         // NOT ok — only return type differs
```

### D. Scope inside a class (9.13)

- **Field scope:** the whole class, regardless of where it's declared.
- **Local variable scope:** from declaration to end of its block.
- **Shadowing:** a local/parameter with the same name as a field *hides* the field. That's why constructors write `this.radius = radius;` — left side is the field, right side is the parameter.

### E. Encapsulation & visibility (9.8–9.9) — THE big idea today

**Encapsulation:** bundle data with the methods that operate on it, and **hide the data** so it can only be changed in controlled ways.

Visibility modifiers (for now, two of them; `protected`/default come in October):
- `public` — accessible from anywhere.
- `private` — accessible **only inside this class** (not even subclasses).

Rule of thumb for CS 1331: **all fields `private`**, expose behavior via `public` methods.

```java
public class BankAccount {
    private double balance;                    // hidden

    public double getBalance() { return balance; }          // accessor / getter

    public void setBalance(double b) {                       // mutator / setter — can VALIDATE
        if (b >= 0) { balance = b; }
    }

    public boolean isOverdrawn() { return balance < 0; }     // boolean getters use "is"
}
```

Why bother?
1. **Validation** — a setter can reject bad values; a public field can't.
2. **Change freedom** — you can rename/re-type the field without breaking callers.
3. **Read-only data** — provide a getter and *no* setter.

Naming convention (Checkstyle will enforce it): `getX()`, `setX(value)`, `isX()` for booleans.

### F. Immutable objects (9.12 — assigned reading)

An object whose state **cannot change after construction** (`String` is the famous example). Recipe:
1. All fields `private`.
2. No setters / no mutator methods.
3. No getter returns a reference to a mutable internal object (return a copy instead).

Immutable objects are safe to alias freely — nobody can change them out from under you.

## 3. Self-check (~5 min)

1. What's wrong?
   ```java
   public class Counter {
       private int count;
       public static void increment() { count++; }
   }
   ```
   <details><summary>Answer</summary><code>count</code> is an instance field; a <code>static</code> method has no object, so <code>count++</code> won't compile. Either make <code>increment</code> non-static or make <code>count</code> static (different meaning!).</details>
2. In `public Circle(double radius) { radius = radius; }`, what does the field end up as?
   <details><summary>Answer</summary>Still <code>0.0</code>. Both sides refer to the parameter (it shadows the field). Need <code>this.radius = radius;</code>.</details>
3. Can two methods `void f(int a, double b)` and `void f(double a, int b)` coexist? What about calling `f(1, 2)`?
   <details><summary>Answer</summary>They can coexist (different parameter types/order). <code>f(1, 2)</code> is ambiguous ⇒ compile error.</details>
4. Why is `public double radius;` discouraged even if it "works"?
   <details><summary>Answer</summary>Anyone can set it to a nonsense value (negative radius) and you can't change the representation later without breaking callers — no encapsulation.</details>
5. Is `Circle c = null; c.getArea();` a compile error or runtime error?
   <details><summary>Answer</summary>Runtime: <code>NullPointerException</code>. It compiles fine.</details>

## 4. Exam 1 (Wed) — compact cheat sheet

Material: through Friday's arrays lecture. **Nothing from today's class is on Exam 1.**

**Types & conversion**
- `byte < short < int < long < float < double`; `char` is numeric (`'a' + 1` is `98`, an `int`).
- Widening is automatic; narrowing needs a cast: `(int) 3.99` → `3` (truncates, no rounding).
- `int / int` is integer division; `7 / 2` → `3`, `7 % 2` → `1`, `-7 / 2` → `-3`, `-7 % 2` → `-1`.
- `x += 1.5` on an `int x` compiles (implicit cast); `x = x + 1.5` does not.
- `5 / 2 * 2.0` → `4.0` (left to right; division happened first as ints).

**Strings**
- Immutable. `s.length()`, `s.charAt(i)`, `s.substring(a, b)` (b exclusive), `s.indexOf`, `s.equals(t)` (**never** `==` for content), `s.compareTo`, `s.toUpperCase()`, `s.trim()`, `s.split(",")`.
- `"" + 1 + 2` → `"12"`; `1 + 2 + ""` → `"3"`.

**Control flow**
- `if / else if / else`; ternary `cond ? a : b`; `switch` (remember `break` in old-style; arrow-style `case X ->` doesn't fall through).
- `while`, `do-while` (body runs at least once), `for`; `break` exits loop, `continue` skips to next iteration.
- Short-circuit `&&`/`||` vs non-short-circuit `&`/`|`.

**I/O**
- `Scanner in = new Scanner(System.in); in.nextInt(); in.nextDouble(); in.next(); in.nextLine();` — the `nextInt()` then `nextLine()` leftover-newline trap.
- `printf("%5.2f|%-10s|%03d%n", ...)`.

**Methods**
- Pass-by-value (copies of primitives / copies of references).
- Overloading resolution & ambiguous invocation.
- Scope; `static` methods can't touch instance data.

**Misc**
- `package` first, then `import`s; `java.lang` auto-imported.
- `Math.pow/sqrt` → `double`; `Math.round(double)` → `long`; `Random.nextInt(n)` → `0..n-1`.
- Enums: `values()`, `valueOf`, `ordinal()`, compare with `==`.
- Arrays: defaults, `.length`, aliasing, for-each is read-only, 2-D ragged rows, array of objects starts as `null`s.

**Exam strategy:** trace code slowly on paper, write out each variable's value line by line; when asked "what's printed", watch types (int vs double formatting: `5` vs `5.0`).
