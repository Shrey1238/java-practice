## 1. Two-minute recap of Monday (Sep 21) — classes & encapsulation

- A class declares **fields** (per-object state) and **methods** (behavior). `new` creates an object; variables hold **references**.
- Instance members belong to objects; `static` members belong to the class. Static methods can't touch instance data.
- **Encapsulation:** fields `private`, behavior `public`. Getters `getX()`/`isX()`, setters `setX()` with validation.
- Shadowing: a parameter named like a field hides it ⇒ `this.x = x;`.
- Immutable class: private fields, no setters, no leaking references.

## 2. Today's concepts

### A. Constructors (9.4)

A constructor initializes a brand-new object. Rules:
- Same name as the class, **no return type** (not even `void` — adding `void` makes it an ordinary method, a classic bug).
- Invoked only via `new`. Never called like a method on an existing object.
- If you write **no constructor**, Java gives you a **default no-arg constructor** that does nothing (fields keep their defaults: `0`, `0.0`, `false`, `null`).
- The moment you write *any* constructor, the free default one **disappears**. `new Circle()` then fails to compile unless you add a no-arg constructor yourself.

```java
public class Student {
    private String name;
    private int credits;

    public Student(String name, int credits) {   // parameterized constructor
        this.name = name;
        this.credits = credits;
    }

    public Student(String name) {                // overloaded constructor
        this.name = name;
        this.credits = 0;
    }

    public Student() {                           // explicit no-arg constructor
        this.name = "Unknown";
        this.credits = 0;
    }
}
```

**Order of initialization when you call `new Student("Ada", 12)`:**
1. Memory allocated; fields set to defaults (`null`, `0`).
2. Field initializers run (e.g. `private int credits = 0;` if written inline).
3. Constructor body runs.

### B. `this` (9.14)

`this` is a reference to **the current object** — the one the method/constructor was called on.

Three uses:
1. **Disambiguate a field from a parameter/local:** `this.name = name;`
2. **Pass the current object to something else:** `registry.add(this);`
3. **Call another constructor of the same class** — `this(...)` (constructor chaining; Monday covers it in depth):
   ```java
   public Student(String name) {
       this(name, 0);          // MUST be the first statement in the constructor
   }
   ```

`this` is **not available in static methods** (there's no current object).

### C. Overloading constructors

Constructors overload exactly like methods: same name (the class name), different parameter lists.

Good practice: put the real initialization logic in **one** "master" constructor (the one with the most parameters) and have the others delegate to it with `this(...)`. That avoids duplicated validation.

```java
public Rectangle(double w, double h) {      // master
    if (w <= 0 || h <= 0) throw new IllegalArgumentException("dimensions must be positive");
    width = w; height = h;
}
public Rectangle(double side) { this(side, side); }   // square
public Rectangle()            { this(1, 1); }         // unit square
```

### D. Typical "design a class" pattern (you'll do this a lot in HW01)

```java
public class Book {
    private String title;          // 1. private fields
    private String author;
    private int pages;

    public Book(String title, String author, int pages) {   // 2. constructor(s)
        this.title = title; this.author = author; this.pages = pages;
    }
    public Book(String title, String author) { this(title, author, 0); }

    public String getTitle() { return title; }               // 3. getters
    public int getPages() { return pages; }

    public void setPages(int pages) {                        // 4. setters with validation
        if (pages >= 0) this.pages = pages;
    }

    public boolean isLongerThan(Book other) {                // 5. behavior
        return this.pages > other.pages;
    }
}
```

Note the last method: inside `Book`, you can access `other.pages` even though it's private — **private is per-class, not per-object**.

## 3. Self-check (~5 min)

1. What's wrong?
   ```java
   public class Dog {
       private String name;
       public void Dog(String name) { this.name = name; }
   }
   Dog d = new Dog("Rex");
   ```
   <details><summary>Answer</summary><code>void Dog(...)</code> is a <em>method</em>, not a constructor. The class has only the default constructor, so <code>new Dog("Rex")</code> doesn't compile.</details>
2. Given only `public Point(int x, int y) {...}`, does `Point p = new Point();` compile?
   <details><summary>Answer</summary>No — writing a constructor removes the implicit default one.</details>
3. Where must `this(...)` appear?
   <details><summary>Answer</summary>As the very first statement of a constructor.</details>
4. Can you use `this` inside `public static void main`?
   <details><summary>Answer</summary>No — static context, no current object.</details>
5. After `Student s = new Student("Bo");` using the class in §2A, what's `s.credits`?
   <details><summary>Answer</summary><code>0</code> (set explicitly in the one-arg constructor).</details>
