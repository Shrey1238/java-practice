## 2. Today's concepts

### A. Constructor chaining (9.14.2)

"Chaining" = one constructor calling another so initialization logic lives in one place.

```java
public class Account {
    private String owner;
    private double balance;
    private static int nextId = 1000;    // see §B
    private final int id;                // final: assigned exactly once (here, in the constructor)

    public Account(String owner, double balance) {   // master constructor
        if (balance < 0) throw new IllegalArgumentException();
        this.owner = owner;
        this.balance = balance;
        this.id = nextId++;
    }
    public Account(String owner) { this(owner, 0.0); }     // chain →
    public Account()             { this("anonymous"); }    // chain → chain →
}
```

Rules & gotchas:
- `this(...)` must be the **first statement**; therefore a constructor can chain to at most **one** other constructor.
- No cycles: A → B → A is a compile error ("recursive constructor invocation").
- Chaining means validation lives in one spot. If you copy-paste the `if (balance < 0)` check into three constructors, you're doing it wrong.
- Preview: in October you'll meet `super(...)`, which chains to the **parent** class's constructor with the same first-statement rule.

### B. `static` on variables (9.7)

A `static` field is shared by **all** objects of the class — there is exactly one copy, living with the class, created when the class is loaded.

```java
public class Player {
    private static int playerCount = 0;   // class variable — shared
    private String name;                  // instance variable — per object

    public Player(String name) {
        this.name = name;
        playerCount++;                    // every construction bumps the shared counter
    }
    public static int getPlayerCount() { return playerCount; }   // static getter for static data
}

new Player("A"); new Player("B");
Player.getPlayerCount();   // 2 — access through the CLASS name
```

When to use `static` fields:
- Counters / ID generators shared across instances.
- **Constants**: `public static final double TAX_RATE = 0.07;` (`static` = one copy, `final` = can't change, `ALL_CAPS` name). This is how `Math.PI` is declared.

When *not* to: anything that describes a particular object (name, balance, radius). A common bug is making a field static "to make the compiler stop complaining" in a static method — that silently turns per-object data into shared data.

Access rules recap:

| From → to | instance member | static member |
|---|---|---|
| instance method | ✓ | ✓ |
| static method | ✗ (no `this`) | ✓ |

You *can* write `obj.staticField`, but don't — it's misleading. Use `ClassName.staticField`.

### C. `null`

`null` is the "points to nothing" value for **reference types** (never for primitives — `int x = null;` won't compile).

- Uninitialized reference **fields** and array slots of reference type default to `null`. Local variables do **not** get a default; you must assign before use.
- Calling anything on `null` ⇒ `NullPointerException` (NPE), the most common runtime error in Java.
  ```java
  String s = null;
  s.length();            // NPE
  s == null              // fine — comparing references
  s.equals("x")          // NPE!   prefer  "x".equals(s)  or check  s != null && s.equals("x")
  ```
- Defensive patterns:
  ```java
  if (name == null || name.isEmpty()) { ... }
  Objects.equals(a, b);   // null-safe equals (java.util.Objects)
  ```
- `null` is a legitimate value meaning "absent" (e.g., `indexOf` returns -1 for ints; for objects you often return `null`). Document it and check for it.
- Assigning `ref = null;` drops your reference; if nothing else refers to the object, it becomes garbage (collected automatically — no `free` in Java).

## 3. Self-check (~5 min)

1. Does this compile?
   ```java
   public Account(String o) { System.out.println("hi"); this(o, 0); }
   ```
   <details><summary>Answer</summary>No — <code>this(...)</code> must be the first statement.</details>
2. What prints?
   ```java
   class C { static int n = 0; int m = 0; C() { n++; m++; } }
   C a = new C(); C b = new C(); C c = new C();
   System.out.println(C.n + " " + a.m + " " + c.m);
   ```
   <details><summary>Answer</summary><code>3 1 1</code></details>
3. Which lines fail, and how?
   ```java
   String[] arr = new String[2];   // 1
   int len = arr.length;           // 2
   int l0 = arr[0].length();       // 3
   int x = null;                   // 4
   ```
   <details><summary>Answer</summary>Line 3: runtime <code>NullPointerException</code>. Line 4: compile error (primitives can't be null). Lines 1–2 are fine (<code>len == 2</code>).</details>
4. How would you declare a shared, unchangeable maximum of 100 students per class?
   <details><summary>Answer</summary><code>public static final int MAX_STUDENTS = 100;</code></details>
5. Why is `"yes".equals(answer)` safer than `answer.equals("yes")`?
   <details><summary>Answer</summary>If <code>answer</code> is <code>null</code>, the first returns <code>false</code>; the second throws an NPE.</details>
