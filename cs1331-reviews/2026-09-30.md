## 2. Today's concepts

### A. Aliasing (again, now with your own classes)

```java
Account a = new Account("Ada", 100);
Account b = a;          // alias: two names, ONE object
b.deposit(50);
a.getBalance();         // 150 — a sees b's change
```

Aliasing is unavoidable and often desired (passing objects to methods is aliasing). It becomes a *bug* when you hand out a reference to something you meant to keep private:

```java
public class Team {
    private String[] roster;
    public String[] getRoster() { return roster; }   // LEAK: caller can now do team.getRoster()[0] = "hacked";
}
```

### B. Copy constructors

A **copy constructor** takes an object of the same class and builds an independent duplicate.

```java
public Team(Team other) {
    this.name = other.name;                       // String is immutable → sharing is safe
    this.roster = other.roster;                   // SHALLOW: both teams share ONE array  ← usually wrong
}
```

**Shallow copy** copies field values. For reference fields, that copies the *reference* → the inner object is shared.

**Deep copy** creates new copies of the mutable inner objects too:

```java
public Team(Team other) {
    this.name = other.name;
    this.roster = Arrays.copyOf(other.roster, other.roster.length);   // DEEP: own array
    // if roster held mutable objects (Player[]), you'd copy each one too:
    // this.players = new Player[other.players.length];
    // for (int i = 0; i < players.length; i++) players[i] = new Player(other.players[i]);
}
```

Decision rule: **immutable field (String, Integer, enum, primitives) → share; mutable field (arrays, your own classes, ArrayList) → copy it.**

Same rule applies to **getters and setters** ("defensive copying"):
```java
public String[] getRoster() { return Arrays.copyOf(roster, roster.length); }
public void setRoster(String[] r) { this.roster = Arrays.copyOf(r, r.length); }
```

Java has a `clone()` mechanism, but this course teaches copy constructors — clearer and no `Cloneable` weirdness.

### C. Class design & interaction

Real programs are several classes that **use** each other. Two relationship words you'll hear:

- **"has-a" (composition / aggregation):** a `Library` has an array of `Book`s; a `Car` has an `Engine`. Implemented as a *field whose type is another class*.
- **"is-a" (inheritance):** a `Dog` is an `Animal`. Starts Friday.

Design checklist for a class (use this for HW01):
1. **One responsibility.** If the description of the class needs "and", consider splitting.
2. **Nouns → classes, adjectives/data → fields, verbs → methods.**
3. Fields `private`; constructors validate; expose only the methods callers need.
4. Who *owns* the data? The owner is responsible for copying it in/out.
5. Interaction happens through method calls, not through reaching into another object's fields.

Example interaction:
```java
public class Library {
    private Book[] books;
    private int count;

    public Library(int capacity) { books = new Book[capacity]; }

    public boolean addBook(Book b) {
        if (b == null || count == books.length) return false;
        books[count++] = b;
        return true;
    }

    public Book findByTitle(String title) {
        for (int i = 0; i < count; i++) {
            if (books[i].getTitle().equals(title)) return books[i];
        }
        return null;                        // documented "not found"
    }
}
```

Note the **partially-filled array** idiom (`count` tracks how many slots are used) — you'll use it until `ArrayList` arrives in late October.

## 3. Self-check (~5 min)

1. After `int[] a = {1,2}; int[] b = a.clone(); b[0] = 9;` what is `a[0]`?
   <details><summary>Answer</summary><code>1</code> — <code>clone()</code> on a 1-D primitive array is a full copy.</details>
2. Is `this.name = other.name;` in a copy constructor a bug when `name` is a `String`?
   <details><summary>Answer</summary>No. Strings are immutable, so sharing is safe.</details>
3. `int[][] g2 = g.clone();` — deep or shallow with respect to the rows?
   <details><summary>Answer</summary>Shallow: the outer array is new, but each row is the same inner array object.</details>
4. Why return `Arrays.copyOf(roster, roster.length)` from a getter instead of `roster`?
   <details><summary>Answer</summary>So callers can't mutate the private array through the returned reference (encapsulation).</details>
5. In `Library.findByTitle`, why loop to `count` rather than `books.length`?
   <details><summary>Answer</summary>Slots ≥ <code>count</code> are <code>null</code>; calling <code>getTitle()</code> on them throws an NPE.</details>
