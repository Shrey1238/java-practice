## 1. Two-minute recap of Wednesday (Oct 7)

- Access: `private` < default (same package) < `protected` (package + subclasses) < `public`.
- **Override** = same signature in subclass; use `@Override`; can't reduce visibility; can't override `static`/`private`/`final`.
- Overriding is resolved at **run time** by the object's actual class; overloading at **compile time** by argument types.
- `super.method()` reuses the parent's implementation.

## 2. Today's concepts

### A. `java.lang.Object` — everyone's superclass (11.6)

Every class ultimately extends `Object`, so every object has these methods (among others):

| method | default behavior (inherited if you don't override) |
|---|---|
| `String toString()` | `ClassName@hexHash`, e.g. `Dog@1b6d3586` — useless |
| `boolean equals(Object o)` | **reference** equality — same as `==` |
| `int hashCode()` | a number derived from the memory address |
| `Class<?> getClass()` | the runtime class object (can't override) |

A "good class" overrides the first three so its objects print nicely, compare by content, and work in hash-based collections.

### B. `toString()` (11.10)

Called automatically by `println(obj)`, string concatenation (`"x: " + obj`), and `String.valueOf(obj)`.

```java
@Override
public String toString() {
    return "Dog[name=" + name + ", breed=" + breed + "]";
    // or: return String.format("Dog[name=%s, breed=%s]", name, breed);
}
```
In a subclass, build on the parent: `return super.toString() + ", tricks=" + tricks;`

### C. `equals()` (11.9) — the recipe

Content equality. The parameter type **must be `Object`** — `equals(Dog other)` is an *overload* that silently isn't used by collections. Standard recipe:

```java
@Override
public boolean equals(Object o) {
    if (this == o) return true;                       // 1. same reference → equal (fast path)
    if (o == null) return false;                      // 2. null is never equal
    if (this.getClass() != o.getClass()) return false; // 3. same runtime class (alt: !(o instanceof Dog))
    Dog other = (Dog) o;                              // 4. cast, now safe
    return this.name.equals(other.name)               // 5. compare fields (equals for objects, == for primitives)
        && this.breed.equals(other.breed);
}
```

Notes:
- Steps 2+3 can be merged when using `instanceof` (`null instanceof X` is `false`).
- Use `getClass()` for strict "same class" equality; `instanceof` lets subclasses be equal to parents (can break symmetry). The course typically teaches `instanceof`; know both.
- Compare object fields with `.equals` (or `Objects.equals(a, b)` for null-safety), primitives with `==`, `double`s ideally with `Double.compare(a, b) == 0`.
- Contract (21.1): reflexive, symmetric, transitive, consistent, `x.equals(null)` is `false`.

### D. `hashCode()` (21.2) — always override with `equals`

Contract: **if `a.equals(b)` then `a.hashCode() == b.hashCode()`.** (Unequal objects *may* share a hash.) Hash-based collections (`HashMap`, `HashSet`, coming in November) find objects by hash first, then `equals` — if you override `equals` without `hashCode`, two "equal" objects land in different buckets and the set thinks they're different.

```java
@Override
public int hashCode() {
    return Objects.hash(name, breed);        // java.util.Objects — combine the same fields used in equals
}
// manual version you may see: 31 * name.hashCode() + breed.hashCode()
```

Rule: **the fields you compare in `equals` are exactly the fields you hash.**

### E. Object equality vocabulary

- `a == b` → same object? (reference/identity equality)
- `a.equals(b)` → same content? (logical equality, if overridden)
- Strings: `==` may be true for literals (interning), false for `new String("x")` — irrelevant trivia except as an exam trap: **always `.equals`**.

## 3. Self-check (~5 min)

1. Why does this `equals` "not work" with an `ArrayList<Point>.contains(p)`?
   ```java
   public boolean equals(Point other) { return x == other.x && y == other.y; }
   ```
   <details><summary>Answer</summary>It's an overload, not an override — the parameter must be <code>Object</code>. Collections call <code>equals(Object)</code>, which is still the inherited reference-equality version. <code>@Override</code> would have caught it.</details>
2. Output?
   ```java
   class P { int x; P(int x) { this.x = x; } }
   P a = new P(1), b = new P(1);
   System.out.println((a == b) + " " + a.equals(b));
   ```
   <details><summary>Answer</summary><code>false false</code> — no override, so <code>equals</code> is reference equality.</details>
3. You override `equals` to compare `id` only. What must `hashCode` use?
   <details><summary>Answer</summary>Only <code>id</code> (or a subset of the equals fields — never a field that equals ignores).</details>
4. Is it legal for two unequal objects to have the same `hashCode()`?
   <details><summary>Answer</summary>Yes (a collision). The contract only constrains <em>equal</em> objects.</details>
5. What does `System.out.println(new int[]{1,2})` print, and why?
   <details><summary>Answer</summary>Something like <code>[I@6d06d69c</code> — arrays don't override <code>toString</code>. Use <code>Arrays.toString</code>.</details>
