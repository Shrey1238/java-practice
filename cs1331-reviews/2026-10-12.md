## 2. Today — finishing the `Object` trio

Expect today to be worked examples + edge cases. Things likely to come up:

### A. `equals` in an inheritance hierarchy

```java
class Animal {
    private String name;
    @Override public boolean equals(Object o) {
        if (!(o instanceof Animal)) return false;
        return name.equals(((Animal) o).name);
    }
}
class Dog extends Animal {
    private String breed;
    @Override public boolean equals(Object o) {
        if (!(o instanceof Dog)) return false;
        Dog d = (Dog) o;
        return super.equals(d) && breed.equals(d.breed);   // reuse parent's comparison
    }
}
```

- `instanceof` version: `animal.equals(dog)` may be `true` while `dog.equals(animal)` is `false` → **asymmetric**. `getClass()` version avoids this but forbids any subclass/superclass equality. Know the trade-off; follow whatever the HW spec says.
- Call `super.equals(o)` to compare the inherited fields rather than duplicating.

### B. `hashCode` in a subclass

```java
@Override public int hashCode() { return Objects.hash(super.hashCode(), breed); }
```

### C. `toString` in a subclass

```java
@Override public String toString() { return super.toString() + " breed=" + breed; }
```

### D. `instanceof` and casting (needed for `equals`; full treatment Oct 19)

```java
Object o = "text";
if (o instanceof String) {                 // true if o's runtime class is String or a subclass
    String s = (String) o;                 // downcast — safe because we checked
}
if (o instanceof Integer i) { ... }        // Java 16+ pattern matching: test and bind in one step
```
A cast that fails at run time throws `ClassCastException`. `null instanceof Anything` is `false`.

### E. Why `equals(Object)` matters for arrays and collections

- `Arrays.equals(a, b)` uses element `.equals`; `Arrays.asList(...).contains(x)` / `ArrayList.indexOf` / `remove(Object)` all call `equals`.
- `HashSet`/`HashMap` call `hashCode` **then** `equals`. Miss one and lookups break.

## 4. Exam 2 cheat sheet (Wed Oct 14) — Sep 21 → today

**Classes & objects**
- Fields (per object) vs static fields (per class). Static methods: no `this`, no instance data.
- Reference vs object; `null`; NPE on dereference; `"x".equals(s)` null-safe.
- Encapsulation: private fields, public getters/setters, validation in setters/constructors. Immutable classes: no setters, no leaked mutable refs.

**Constructors**
- Class name, no return type. Writing any constructor removes the default one.
- `this(...)` / `super(...)` must be first statement; not both; no cycles.
- Implicit `super()` if none written → error if parent lacks no-arg constructor.
- Order: parent constructor body → child field initializers → child constructor body.
- Copy constructor: shallow (share refs) vs deep (copy mutable inner objects). Strings can be shared.

**`this`**: current object; disambiguate shadowed fields; pass self; chain constructors. Unavailable in static context.

**`static` & `final`**
- `static` field: one shared copy; access via `ClassName.x`.
- `static final` constant: `MAX_SIZE`.
- `final` variable: assign once; `final` method: no override; `final` class: no subclass.

**Wrappers**: `Integer`/`Double`…; autoboxing; `parseInt`; compare with `equals`; unboxing `null` ⇒ NPE.

**Inheritance**
- `extends`; single inheritance; everything extends `Object`.
- `private` inherited but inaccessible; `protected` = package + subclasses; default = package.
- Constructors not inherited. `super.method()`.
- Overriding: same signature, `@Override`, no narrowing visibility, not for `static`/`private`/`final`. Run-time dispatch by actual object type.
- Overloading: different parameter list, compile-time resolution.
- `Parent p = new Child();` legal; `p.childOnlyMethod()` compile error.

**`Object` methods**: `toString`, `equals(Object)` recipe, `hashCode` contract & `Objects.hash`. `==` vs `equals`.

**Typical exam question types**
1. "What is printed?" with constructor chains and `super`/`this` prints → write the call order.
2. "Does this compile? If not, why?" → check: return type on constructor, `this()` placement, missing parent no-arg ctor, private access from subclass, override visibility, static touching instance.
3. "Write a class…" → private fields, constructor(s), getters/setters, `equals`/`hashCode`/`toString`. Practice writing the `equals` recipe from memory **five times** before Wednesday.
4. Overriding vs overloading identification.
