## 1. Recap (what abstract classes build on)

- `class Dog extends Animal` — Dog inherits, can override with same signature + `@Override`.
- `Animal a = new Dog();` — variable's *compile-time type* is `Animal`, *run-time type* is `Dog`; `a.speak()` runs Dog's version.
- Constructors chain to the parent with `super(...)`.
- `final class` → can't be extended; `final` method → can't be overridden.

## 2. Today's concepts

### A. The motivation

`Animal.speak()` returning `"..."` is a placeholder — there's no sensible default. What we want: *every* Animal **must** have `speak()`, but only concrete animals know how. That's an **abstract method**, and a class containing one must be **abstract**.

### B. Syntax

```java
public abstract class Shape {
    private String color;                                  // abstract classes CAN have fields

    public Shape(String color) { this.color = color; }     // ...and constructors (called via super)

    public String getColor() { return color; }             // ...and concrete methods

    public abstract double area();                         // no body; semicolon. Subclasses MUST implement.

    @Override
    public String toString() {                             // concrete method may call abstract ones
        return color + " shape with area " + area();
    }
}

public class Circle extends Shape {
    private double r;
    public Circle(String color, double r) { super(color); this.r = r; }
    @Override public double area() { return Math.PI * r * r; }
}
```

### C. The rules

1. **Cannot instantiate** an abstract class: `new Shape("red")` is a compile error. But `Shape s = new Circle("red", 2);` is fine — the *variable* can be abstract-typed.
2. Any class with ≥1 abstract method **must** be declared `abstract`. An abstract class may have **zero** abstract methods (just to block instantiation).
3. A concrete subclass **must implement all** inherited abstract methods, or it too must be declared `abstract`.
4. Abstract methods have **no body** and cannot be `private`, `static`, or `final` (all of those prevent overriding — contradiction).
5. Abstract classes **do** have constructors — subclasses call them with `super(...)`. You just can't call them with `new` directly.
6. Abstract classes can have `static` methods, fields, constants, concrete methods — everything a normal class has.
7. `Shape[] shapes = { new Circle(...), new Rect(...) };` → the whole point: treat different concrete types uniformly and call `area()` on each (polymorphism, formally Monday).

### D. `abstract` vs `final` — opposites

| | `abstract` | `final` |
|---|---|---|
| on a class | must be subclassed to be useful; can't `new` | cannot be subclassed at all |
| on a method | has no body; *must* be overridden | *cannot* be overridden |
| together? | `abstract final` is a compile error (contradictory) | |

`final class` use cases: `String`, `Integer`, `Math` — immutability/safety guarantees you don't want a subclass to break.

### E. Common "does it compile?" traps

```java
abstract class A { abstract void f(); }
class B extends A { }                     // ✗ B must implement f() or be abstract
abstract class C extends A { }            // ✓ C defers f() to its subclasses
A a = new A();                            // ✗ can't instantiate abstract
A a2 = new B2();                          // ✓ if B2 is a concrete subclass
abstract class D { void g(); }            // ✗ non-abstract method needs a body
class E { abstract void h(); }            // ✗ class must be abstract
```

## 3. Self-check (~5 min)

1. Can an abstract class have a constructor? When does it run?
   <details><summary>Answer</summary>Yes. It runs when a concrete subclass is instantiated, via the subclass's (explicit or implicit) <code>super(...)</code>.</details>
2. `abstract class Vehicle { }` — is it legal with no abstract methods? Why would you?
   <details><summary>Answer</summary>Legal. To prevent <code>new Vehicle()</code> while sharing code among subclasses.</details>
3. Output?
   ```java
   abstract class Q { Q() { System.out.print(name()); } abstract String name(); }
   class R extends Q { String name() { return "R"; } }
   new R();
   ```
   <details><summary>Answer</summary><code>R</code> — the abstract constructor calls the overridden method; dispatch picks <code>R.name()</code>. (Calling overridable methods from a constructor is risky in practice because subclass fields aren't initialized yet, but it does compile and run.)</details>
4. Which one is invalid: `public abstract void a();` / `private abstract void b();` / `abstract static void c();`
   <details><summary>Answer</summary>Both <code>b</code> and <code>c</code> — private and static methods can't be overridden, so they can't be abstract.</details>
5. `Shape s = new Circle("red", 1); s.getRadius();` compiles?
   <details><summary>Answer</summary>No — <code>Shape</code> has no <code>getRadius()</code>. Cast first: <code>((Circle) s).getRadius()</code>.</details>
