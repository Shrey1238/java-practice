## 2. Today's concepts

### A. What polymorphism means

"Many forms": one reference type, many possible runtime object types, and the **object** decides which overridden method runs.

```java
Shape[] shapes = { new Circle(1), new Rectangle(2, 3), new Triangle(3, 4) };
double total = 0;
for (Shape s : shapes) {
    total += s.area();           // each element runs ITS OWN area() — dynamic binding
}
```
You wrote one loop; adding `Hexagon` later requires zero changes here. That's the payoff.

### B. Static (compile-time) type vs. dynamic (run-time) type

```java
Shape s = new Circle(1);
//  ^ static type          ^ dynamic type
```

| question | decided by |
|---|---|
| "Does `s.foo()` compile?" | **static type** — `Shape` must declare `foo()` |
| "Which `foo()` body runs?" | **dynamic type** — most-derived override in `Circle` |
| Which *overload* is chosen? | static types of the **arguments**, at compile time |
| Fields (`s.x`) and `static` methods | **static type** — fields/statics are *not* polymorphic |

Mantra: **compiler checks the reference; JVM dispatches on the object.**

### C. Upcasting — always safe, implicit

```java
Circle c = new Circle(1);
Shape s = c;                  // implicit upcast — a Circle IS-A Shape
Object o = c;                 // everything IS-A Object
```
You lose *access* to Circle-only members through `s`, but the object is unchanged.

### D. Downcasting — explicit, checked at run time

```java
Shape s = new Circle(1);
Circle c = (Circle) s;                 // ✓ compiles; ✓ runs (object really is a Circle)
Rectangle r = (Rectangle) s;           // ✓ compiles; ✗ ClassCastException at run time
String str = (String) s;               // ✗ compile error — Shape and String are unrelated
```

Guard with `instanceof`:

```java
if (s instanceof Circle) {
    Circle c = (Circle) s;
    c.getRadius();
}
// Java 16+ pattern matching (allowed in course unless told otherwise):
if (s instanceof Circle c) { c.getRadius(); }
```

`x instanceof T` is true when x's runtime class is `T` or any subclass of `T` (and false for `null`).

### E. Method dispatch worked example

```java
class A { String who() { return "A"; } String call() { return who(); } }
class B extends A { @Override String who() { return "B"; } }

A a = new B();
a.who();      // "B"  — override, dynamic
a.call();     // "B"  — call() is inherited, but the who() inside it still dispatches on the object → B
```

### F. Overloading + polymorphism trap

```java
void print(Shape s)  { System.out.println("shape"); }
void print(Circle c) { System.out.println("circle"); }

Shape s = new Circle(1);
print(s);      // "shape"  — overload chosen by STATIC type of the argument
```

### G. Arrays/parameters of a supertype

```java
public static double totalArea(Shape[] shapes) { ... }    // accepts Circle[]? Yes (array covariance) — but careful storing
public static void describe(Shape s) { ... }              // describe(new Circle(1)) works — parameter upcast
```

## 3. Self-check (~6 min)

1. Output?
   ```java
   class P { int x = 1; int get() { return x; } }
   class Q extends P { int x = 2; @Override int get() { return x; } }
   P p = new Q();
   System.out.println(p.x + " " + p.get());
   ```
   <details><summary>Answer</summary><code>1 2</code> — fields resolve by static type (P), methods by dynamic type (Q).</details>
2. Which line fails, and when (compile vs. run)?
   ```java
   Object o = new Circle(1);
   Shape s = o;               // L1
   Shape s2 = (Shape) o;      // L2
   Rectangle r = (Rectangle) o;   // L3
   ```
   <details><summary>Answer</summary>L1: compile error (needs explicit downcast). L2: fine. L3: compiles, <code>ClassCastException</code> at run time.</details>
3. `Shape s = new Circle(1); s.getRadius();` — fix without changing `Shape`.
   <details><summary>Answer</summary><code>((Circle) s).getRadius()</code>, ideally guarded by <code>instanceof</code>.</details>
4. True/false: `static` methods are dispatched polymorphically.
   <details><summary>Answer</summary>False — resolved by static type. (Subclass static with same signature "hides" rather than overrides.)</details>
5. Why is `Shape[] shapes` + a loop calling `area()` better than an `if (s instanceof Circle) ... else if (s instanceof Rectangle) ...` chain?
   <details><summary>Answer</summary>Open for extension: new subclasses need no changes to the loop; logic lives with the data (each class owns its <code>area()</code>).</details>
