## 2. Today's concepts

### A. Interface = a pure contract

```java
public interface Drawable {
    int MAX_LAYERS = 10;              // implicitly public static final
    void draw();                      // implicitly public abstract
    default String label() {          // default method (Java 8+): has a body, inheritable
        return "drawable";
    }
    static Drawable empty() { ... }   // static methods allowed (call via Drawable.empty())
}

public class Circle extends Shape implements Drawable, Comparable<Circle> {
    @Override public void draw() { ... }             // must be public!
    @Override public int compareTo(Circle o) { ... }
}
```

Rules:
1. Methods are `public abstract` by default (writing `public` is redundant; writing nothing else is normal). Implementing method **must be `public`** — forgetting it is the #1 compile error ("attempting to assign weaker access privileges").
2. No instance fields, no constructors, can't be instantiated. Only constants.
3. A class `implements` any number of interfaces (comma-separated) while `extends` only one class. `extends` comes before `implements`.
4. An interface can `extends` other interfaces (even several).
5. A concrete class must implement **all** abstract methods from all its interfaces — or be declared `abstract`.
6. Interface types are reference types: `Drawable d = new Circle(1);` and `Drawable[] items`, `instanceof Drawable`, casting — all work exactly like with superclasses.

### B. Abstract class vs interface — when to use which

| | abstract class | interface |
|---|---|---|
| relationship | **is-a**, shares implementation & state | **can-do** capability, no state |
| fields | yes (any) | constants only |
| constructors | yes | no |
| multiple? | one superclass | many interfaces |
| method bodies | any | `default`/`static` only |

Rule of thumb: shared *code/fields* → abstract class; shared *ability across unrelated classes* (`Comparable`, `Iterable`) → interface.

### C. `Comparable<T>` (13.8) — natural ordering

```java
public interface Comparable<T> { int compareTo(T other); }
```

Contract: return **negative** if `this < other`, **zero** if equal, **positive** if `this > other`. (Only the sign matters.) Should be consistent with `equals`.

```java
public class Student implements Comparable<Student> {
    private String name; private double gpa;

    @Override
    public int compareTo(Student other) {
        int byGpa = Double.compare(other.gpa, this.gpa);      // descending GPA (note the order)
        if (byGpa != 0) return byGpa;
        return this.name.compareTo(other.name);               // tie-break: String's own compareTo
    }
}
```

Idioms:
- ints: `Integer.compare(a, b)` — **not** `a - b` (overflow risk).
- doubles: `Double.compare(a, b)` — never `(int)(a - b)`.
- Strings: `s1.compareTo(s2)` (lexicographic, case-sensitive) or `compareToIgnoreCase`.
- Reverse an ordering by swapping arguments.

Why it matters: `Arrays.sort(studentArray)` and `Collections.sort(list)` require elements to be `Comparable` — this is what the sorting lectures (Oct 28–Nov 2) will use ("sorting with polymorphism").

### D. Type parameter `<T>` preview

`Comparable<Student>` means `compareTo` takes a `Student`, not `Object` — no casting needed. The raw `Comparable` (no `<T>`) forces `compareTo(Object)` + a cast: avoid it. More on generics Friday.

## 3. Self-check (~6 min)

1. Does this compile?
   ```java
   interface Flyer { void fly(); }
   class Bird implements Flyer { void fly() { } }
   ```
   <details><summary>Answer</summary>No — <code>fly()</code> in Bird has default access, weaker than the interface's implicit <code>public</code>.</details>
2. `class Bat extends Mammal implements Flyer, Comparable<Bat>` — legal? What must Bat provide?
   <details><summary>Answer</summary>Legal. Must provide public <code>fly()</code> and public <code>int compareTo(Bat)</code> (plus any abstract methods from Mammal).</details>
3. `compareTo` returns `this.age - other.age`. When is that wrong?
   <details><summary>Answer</summary>Integer overflow for extreme values (e.g. <code>Integer.MIN_VALUE - 1</code>) flips the sign. Use <code>Integer.compare</code>.</details>
4. Can you write `new Comparable<Student>()`? `Comparable<Student> c = new Student(...)`?
   <details><summary>Answer</summary>No (interface can't be instantiated — ignoring anonymous classes). Yes, if Student implements it.</details>
5. Interface `A` declares `int X = 5;`. Can an implementing class do `X = 6;`?
   <details><summary>Answer</summary>No — interface fields are implicitly <code>public static final</code>.</details>
