## 2. Today's concepts

### A. Why `ArrayList`

Arrays are fixed-length. `java.util.ArrayList<E>` wraps an array, grows automatically, and gives you methods.

```java
import java.util.ArrayList;

ArrayList<String> names = new ArrayList<>();          // diamond <> infers <String>
names.add("Ann");                  // append → [Ann]
names.add("Cy");                   // [Ann, Cy]
names.add(1, "Bo");                // insert at index, shifts right → [Ann, Bo, Cy]
names.get(0);                      // "Ann"
names.set(2, "Cid");               // replace → [Ann, Bo, Cid]
names.remove(0);                   // by INDEX, shifts left → [Bo, Cid]; returns removed element
names.remove("Cid");               // by OBJECT (uses equals) → [Bo]; returns boolean
names.size();                      // 1   (not .length, not .length())
names.contains("Bo");              // true (equals)
names.indexOf("Zed");              // -1
names.isEmpty(); names.clear();
System.out.println(names);         // [Bo] — ArrayList has a real toString
```

### B. Array vs ArrayList cheat sheet

| | array | `ArrayList<E>` |
|---|---|---|
| size | fixed, `.length` (field) | grows, `.size()` (method) |
| access | `a[i]` | `list.get(i)` / `list.set(i, x)` |
| element types | primitives **or** objects | **objects only** → `ArrayList<Integer>`, never `ArrayList<int>` |
| print | `Arrays.toString(a)` | `println(list)` works |
| equality | `Arrays.equals` | `list.equals(other)` element-wise |
| for-each | ✓ | ✓ |

### C. Autoboxing and the `remove` trap

```java
ArrayList<Integer> nums = new ArrayList<>();
nums.add(5);                 // autobox int → Integer
int x = nums.get(0);         // unbox

nums.add(10); nums.add(20);  // [5, 10, 20]
nums.remove(1);              // remove(int index) → removes 10 → [5, 20]
nums.remove(Integer.valueOf(20));   // remove(Object) → removes the VALUE 20 → [5]
```
Overload resolution picks `remove(int)` for an `int` argument — index, not value. Classic exam question.

### D. Generics — using them (19.1–19.2)

`ArrayList<E>` is a **generic class**; `E` is a type parameter you fill in. Benefits:
- **Compile-time type safety**: `names.add(42)` is rejected.
- **No casts**: `String s = names.get(0);` instead of `(String) rawList.get(0)`.

```java
ArrayList<Student> roster = new ArrayList<>();
ArrayList<int[]> rows = new ArrayList<>();         // type argument can be any reference type, even arrays
ArrayList<ArrayList<Integer>> grid = new ArrayList<>();
ArrayList list = new ArrayList();                  // "raw type" — compiles with warning; avoid
```

`ArrayList<Circle>` is **not** a subtype of `ArrayList<Shape>` (generics are invariant) — even though `Circle` is a `Shape`. Bounded wildcards (`? extends Shape`) fix this — coming Nov 2.

### E. Iterating and modifying

```java
for (String n : names) { ... }                 // read-only traversal
for (int i = 0; i < names.size(); i++) { ... } // when you need the index or to set()

// Removing while iterating: iterate BACKWARDS with an index, or use an Iterator (Nov 6)
for (int i = names.size() - 1; i >= 0; i--) {
    if (names.get(i).isEmpty()) names.remove(i);
}
// for-each + remove → ConcurrentModificationException
```

### F. `List` interface preview

`ArrayList<E>` implements `List<E>`; idiomatic Java declares `List<String> names = new ArrayList<>();` (program to the interface — polymorphism from Monday!). Both forms are fine in this course unless the HW specifies.
