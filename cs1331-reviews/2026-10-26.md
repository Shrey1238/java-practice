## 2. Today's concepts

### A. The question Big-O answers

"As input size *n* grows, how does the **number of basic operations** grow?" — ignoring constants and machine speed. It's about *growth rate*, not seconds.

### B. Definition (22.1)

`f(n)` is **O(g(n))** if there exist constants *c* > 0 and *n₀* such that `f(n) ≤ c·g(n)` for all `n ≥ n₀`. Informally: eventually, `f` is bounded above by a constant multiple of `g`.

Simplification rules:
1. **Drop constants**: `5n` → O(n); `n/2` → O(n).
2. **Keep the dominant term**: `n² + 100n + 7` → O(n²).
3. `O(1)` = constant, independent of *n*.

### C. The ladder (memorize, smallest → largest)

| class | name | typical example |
|---|---|---|
| O(1) | constant | array index, `ArrayList.get`, arithmetic, `HashMap.get` (later) |
| O(log n) | logarithmic | binary search; halving loops |
| O(n) | linear | single loop over data; linear search; `ArrayList.contains`; `add(0, x)` |
| O(n log n) | linearithmic | merge sort; `Arrays.sort` on objects |
| O(n²) | quadratic | nested loop over the same data; selection/bubble/insertion sort |
| O(2ⁿ) | exponential | naive recursive Fibonacci |

`log n` here is log₂, but base doesn't matter in Big-O (constant factor).

### D. Reading code for Big-O

```java
for (int i = 0; i < n; i++) { ... }                       // O(n)
for (int i = 0; i < n; i++)
    for (int j = 0; j < n; j++) { ... }                   // O(n²)
for (int i = 0; i < n; i++)
    for (int j = i + 1; j < n; j++) { ... }               // n(n-1)/2 iterations → still O(n²)
for (int i = 1; i < n; i *= 2) { ... }                    // O(log n) — i doubles
for (int i = 0; i < n; i++)                               // O(n log n)
    for (int j = 1; j < n; j *= 2) { ... }
for (int i = 0; i < n; i++) { ... }
for (int j = 0; j < n; j++) { ... }                       // sequential, not nested → O(n) + O(n) = O(n)
for (int i = 0; i < n; i++)
    for (int j = 0; j < 10; j++) { ... }                  // inner bound is constant → O(n)
```

Method calls count too: a loop that calls an O(n) method (e.g. `list.contains(x)`) *n* times is O(n²).

### E. Best / worst / average case

Linear search for `x` in an array of *n*:
- best: `x` at index 0 → O(1)
- worst: not present → O(n)
- average: ~n/2 comparisons → O(n)

Unless told otherwise, **Big-O in this class means worst case.**

### F. Space complexity

Same idea for extra memory. Copying an array → O(n) space; swapping in place → O(1) extra space. Merge sort (Nov 4) uses O(n) extra; selection/bubble/insertion use O(1).

### G. Big-O of things you already use

| operation | cost |
|---|---|
| `arr[i]`, `list.get(i)`, `list.set(i, x)` | O(1) |
| `list.add(x)` at end | O(1) amortized (occasional O(n) resize) |
| `list.add(0, x)`, `list.remove(0)` | O(n) — shift everything |
| `list.contains(x)`, `indexOf` | O(n) |
| `String` concatenation in a loop | O(n²) overall — use `StringBuilder` |
| `Arrays.sort(int[])` | O(n log n) |

## 3. Self-check (~6 min)

1. `3n² + 2n log n + 500` is O(?)
   <details><summary>Answer</summary>O(n²)</details>
2. Big-O of:
   ```java
   int count = 0;
   for (int i = 0; i < n; i++)
       for (int j = 0; j < i; j++) count++;
   ```
   <details><summary>Answer</summary>O(n²) — inner loop runs 0+1+…+(n−1) = n(n−1)/2 times.</details>
3. Big-O of:
   ```java
   while (n > 1) { n = n / 2; }
   ```
   <details><summary>Answer</summary>O(log n)</details>
4. Removing all elements from an `ArrayList` by repeatedly calling `remove(0)` — total cost?
   <details><summary>Answer</summary>O(n²): each <code>remove(0)</code> shifts the rest (O(n)), done <em>n</em> times. Removing from the end each time would be O(n) total.</details>
5. Is an O(n) algorithm always faster than an O(n²) one?
   <details><summary>Answer</summary>Not for small <em>n</em> — constants matter; Big-O describes behavior as <em>n</em> grows.</details>
6. True/false: O(n) + O(n) = O(2n), which is a different class.
   <details><summary>Answer</summary>False — constants are dropped; O(2n) = O(n).</details>
