## 2. Today's concepts

### A. Linear search — O(n), any array

```java
public static int linearSearch(int[] a, int target) {
    for (int i = 0; i < a.length; i++) {
        if (a[i] == target) return i;      // .equals for objects
    }
    return -1;
}
```

### B. Binary search — O(log n), **requires sorted input**

```java
public static int binarySearch(int[] a, int target) {
    int lo = 0, hi = a.length - 1;
    while (lo <= hi) {                        // <= : a 1-element range still needs checking
        int mid = lo + (hi - lo) / 2;         // avoids overflow of (lo + hi)
        if (a[mid] == target) return mid;
        else if (a[mid] < target) lo = mid + 1;
        else hi = mid - 1;
    }
    return -1;
}
```

Trace `a = {2, 5, 8, 12, 16, 23}`, target 16: `lo=0,hi=5,mid=2 (8<16) → lo=3; mid=4 (16) → return 4`. Two comparisons for n=6; in general ≤ ⌊log₂ n⌋ + 1.

Library versions: `Arrays.binarySearch(arr, x)`, `Collections.binarySearch(list, x)` (return a negative "insertion point" encoding when absent).

### C. Selection sort (7.11) — O(n²), in-place

Idea: for each position `i`, find the **smallest** element in `[i, n)` and swap it into `i`.

```java
public static void selectionSort(int[] a) {
    for (int i = 0; i < a.length - 1; i++) {
        int minIdx = i;
        for (int j = i + 1; j < a.length; j++) {
            if (a[j] < a[minIdx]) minIdx = j;
        }
        int tmp = a[i]; a[i] = a[minIdx]; a[minIdx] = tmp;    // swap (harmless when minIdx == i)
    }
}
```

Trace `{5, 2, 4, 1}`:
- i=0: min is 1 → `{1, 2, 4, 5}`
- i=1: min is 2 → unchanged
- i=2: min is 4 → unchanged → done.

Properties: always n(n−1)/2 comparisons (best = worst = O(n²)); at most n−1 swaps; O(1) extra space; **not stable**.

### D. "With polymorphism" — sorting `Comparable` objects

Replace `<` with `compareTo` and make the method generic-ish:

```java
public static void selectionSort(Comparable[] a) {          // raw Comparable — what the textbook shows
    for (int i = 0; i < a.length - 1; i++) {
        int minIdx = i;
        for (int j = i + 1; j < a.length; j++) {
            if (a[j].compareTo(a[minIdx]) < 0) minIdx = j;  // dynamic dispatch → Student.compareTo, Circle.compareTo, ...
        }
        Comparable tmp = a[i]; a[i] = a[minIdx]; a[minIdx] = tmp;
    }
}

// Cleaner, generic version (bounded type — full treatment Nov 2):
public static <T extends Comparable<T>> void selectionSort(T[] a) { ... a[j].compareTo(a[minIdx]) < 0 ... }
```

One sort works for **any** class implementing `Comparable` — that's the polymorphism: the algorithm calls `compareTo`, and each element's class decides what "less than" means.

### E. Library sorting

`Arrays.sort(arr)` / `Collections.sort(list)` — elements must be `Comparable` (or pass a `Comparator`). O(n log n). Use these in HWs unless told to implement your own.

   <details><summary>Answer</summary>The halving decision (go left/right) assumes order; on unsorted data you may discard the half containing the target.</details>
3. Selection sort on an already-sorted array of 1000 elements: roughly how many comparisons?
   <details><summary>Answer</summary>Still ~500,000 (n(n−1)/2) — selection sort doesn't detect sortedness.</details>

   <details><summary>Answer</summary><code>{1, 3, 5, 7, 9}</code> — pass 1 swaps 9↔1 → {1,7,5,3,9}; pass 2 swaps 7↔3 → {1,3,5,7,9}.</details>
