## 2. Today's concepts

### A. Insertion sort (23.1)

Idea: keep a sorted prefix `[0, i)`; take `a[i]` and **shift** larger elements right until it slots in — like sorting cards in your hand.

```java
public static void insertionSort(int[] a) {
    for (int i = 1; i < a.length; i++) {
        int key = a[i];
        int j = i - 1;
        while (j >= 0 && a[j] > key) {      // shift right while bigger (strict > keeps it stable)
            a[j + 1] = a[j];
            j--;
        }
        a[j + 1] = key;                     // drop key into the gap
    }
}
```

Trace `{5, 2, 4, 1}`: i=1 key=2 → `{2,5,4,1}`; i=2 key=4 → `{2,4,5,1}`; i=3 key=1 → `{1,2,4,5}`.

| | insertion |
|---|---|
| best (sorted) | O(n) — one comparison per element |
| worst (reverse) | O(n²) |
| stable | yes |
| adaptive | yes — nearly-sorted input is ~O(n) |
| space | O(1) |

Insertion beats bubble in practice (shifts, not swaps); it's what library sorts use for tiny subarrays.

### B. Merge sort — intro (details Wed with recursion)

Divide & conquer: split in half, sort each half (recursively), **merge** the two sorted halves in O(n). Depth log n × O(n) per level → **O(n log n)** always. Stable. Needs O(n) extra space.

The merge step is the part to understand today:
```java
// merge sorted left[] and right[] into result[]
int i = 0, j = 0, k = 0;
while (i < left.length && j < right.length) {
    result[k++] = (left[i] <= right[j]) ? left[i++] : right[j++];   // <= keeps stability
}
while (i < left.length)  result[k++] = left[i++];
while (j < right.length) result[k++] = right[j++];
```

### C. Exceptions demo (full coverage async, 12.1–12.9 — on Exam 3)

What you'll likely see demoed:
```java
try {
    int[] a = new int[3];
    a[5] = 1;                                  // ArrayIndexOutOfBoundsException
} catch (ArrayIndexOutOfBoundsException e) {
    System.out.println("bad index: " + e.getMessage());
} finally {
    System.out.println("always runs");
}
```
- **Unchecked** (`RuntimeException` subclasses: NPE, `ArrayIndexOutOfBounds`, `IllegalArgumentException`, `ClassCastException`, `ArithmeticException`) — compiler doesn't force handling.
- **Checked** (`IOException`, `FileNotFoundException`…) — must `try/catch` or declare `throws`.
- `throw new IllegalArgumentException("radius < 0")` in constructors/setters for validation — you've been doing this.
- Catch order: subclasses before superclasses, or the later catch is unreachable (compile error).

### D. Generics — bounded types and wildcards (19.x)

**Bounded type parameter** (you've seen it):
```java
public static <T extends Comparable<T>> T max(T[] a) { ... }     // T must be Comparable to itself
```

**The problem wildcards solve:** `ArrayList<Circle>` is *not* an `ArrayList<Shape>`, so `double total(ArrayList<Shape> list)` rejects a list of circles.

```java
// ? extends T  — "some unknown subtype of T": READ as T, can't add (except null)
public static double total(ArrayList<? extends Shape> list) {
    double sum = 0;
    for (Shape s : list) sum += s.area();       // reading is safe
    // list.add(new Circle(1));                 // ✗ compiler doesn't know the exact element type
    return sum;
}

// ? super T  — "some unknown supertype of T": can ADD T, reads come out as Object
public static void addCircles(ArrayList<? super Circle> list) {
    list.add(new Circle(1));                    // safe: whatever it is, it accepts Circles
    Object o = list.get(0);                     // reads are only Object
}

// ?  — unbounded: read as Object, add nothing
public static void printAll(ArrayList<?> list) { for (Object o : list) System.out.println(o); }
```

**PECS** — *Producer Extends, Consumer Super*: if the collection **produces** values for you → `? extends`; if it **consumes** values you put in → `? super`.

Why `Comparable<? super T>` shows up: `<T extends Comparable<? super T>>` lets a `Dog` be sorted using `compareTo` inherited from `Animal implements Comparable<Animal>`.
