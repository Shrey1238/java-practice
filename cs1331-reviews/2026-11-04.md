## 2. Today's concepts

### A. Recursion — anatomy (18)

A method that calls itself on a **smaller** problem. Every recursive method needs:
1. **Base case(s)** — smallest input, answered directly, no recursive call.
2. **Recursive case** — do a little work, call yourself on a strictly smaller input, combine.

```java
public static int factorial(int n) {
    if (n <= 1) return 1;                 // base case
    return n * factorial(n - 1);          // recursive case: n * (smaller problem)
}
```

Call stack for `factorial(3)`: `f(3)` waits on `f(2)` waits on `f(1)`=1 → `f(2)`=2 → `f(3)`=6. Each pending call is a **stack frame**; missing/unreachable base case → `StackOverflowError`.

### B. Patterns you should be able to write cold

```java
// sum of array — recurse on index
static int sum(int[] a, int i) { return (i == a.length) ? 0 : a[i] + sum(a, i + 1); }

// string reverse
static String rev(String s) { return s.isEmpty() ? "" : rev(s.substring(1)) + s.charAt(0); }

// palindrome
static boolean pal(String s) {
    if (s.length() < 2) return true;
    return s.charAt(0) == s.charAt(s.length() - 1) && pal(s.substring(1, s.length() - 1));
}

// power
static int pow(int b, int e) { return (e == 0) ? 1 : b * pow(b, e - 1); }

// fibonacci (naive) — O(2ⁿ): the classic "why recursion can be slow" example
static int fib(int n) { return (n < 2) ? n : fib(n - 1) + fib(n - 2); }

// binary search, recursive
static int bs(int[] a, int t, int lo, int hi) {
    if (lo > hi) return -1;
    int mid = lo + (hi - lo) / 2;
    if (a[mid] == t) return mid;
    return (a[mid] < t) ? bs(a, t, mid + 1, hi) : bs(a, t, lo, mid - 1);
}
```

Helper-method idiom: public `sum(int[] a)` calls private `sum(a, 0)` so callers don't pass the index.

**Tracing tip for exams:** write each call on its own line with indentation; resolve from the deepest call back up. Watch whether work happens *before* the recursive call (top-down, e.g. print then recurse) or *after* (bottom-up, e.g. recurse then print → reversed order).

### C. Merge sort (23.4) — recursion applied

```java
public static void mergeSort(int[] a) {
    if (a.length < 2) return;                                    // base case
    int mid = a.length / 2;
    int[] left  = Arrays.copyOfRange(a, 0, mid);
    int[] right = Arrays.copyOfRange(a, mid, a.length);
    mergeSort(left);                                             // sort halves
    mergeSort(right);
    merge(left, right, a);                                       // combine (Monday's merge, writing into a)
}
```

- Always **O(n log n)**: log n levels of splitting × O(n) merging per level. Best = worst.
- O(n) extra space (the temp arrays). Stable if merge uses `<=`.
- First O(n log n) sort you've seen — beats the O(n²) trio for large n.

### D. ADTs (10.2)

An **Abstract Data Type** specifies **what** operations exist and what they mean — *not how* they're implemented. Interface = ADT; class = implementation. Users code against the ADT, so implementations can be swapped (polymorphism again).

### E. The List ADT (24.1–24.3)

Operations: `add(x)`, `add(i, x)`, `get(i)`, `set(i, x)`, `remove(i)`, `size()`, `isEmpty()`, `contains(x)`, `indexOf(x)`, `clear()`.

Two implementations you'll compare:

| op | array-backed (`ArrayList`) | linked (`LinkedList`, Friday) |
|---|---|---|
| `get(i)` | O(1) | O(n) |
| `add` at end | O(1) amortized | O(1) with tail pointer |
| `add(0, x)` / `remove(0)` | O(n) shift | O(1) |
| `add(i, x)` middle | O(n) shift | O(n) walk + O(1) link |
| memory | contiguous, may have slack | per-node overhead |

You may be asked to sketch an array-backed list: fields `E[] backing; int size;`, with a `resize()` that doubles the array when full (`(E[]) new Object[cap]` — the unchecked cast is the standard idiom, with `@SuppressWarnings("unchecked")`).
