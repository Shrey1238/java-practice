## 2. Today's concepts

### A. Writing a generic class

```java
public class Box<T> {                        // T is a type parameter; convention: T, E, K, V
    private T item;
    public Box(T item) { this.item = item; }
    public T get() { return item; }
    public void set(T item) { this.item = item; }
}
Box<String> b = new Box<>("hi");
String s = b.get();                          // no cast
```

Multiple parameters: `class Pair<K, V> { K key; V value; }`.

### B. Generic methods

Type parameter declared **before the return type**:
```java
public static <T> void swap(T[] a, int i, int j) { T tmp = a[i]; a[i] = a[j]; a[j] = tmp; }
public static <T extends Comparable<T>> T max(T a, T b) { return a.compareTo(b) >= 0 ? a : b; }
public static <K, V> V lookup(Pair<K, V>[] pairs, K key) { ... }
```
A generic method can live in a non-generic class; a `static` method **cannot** use the class's `T` (no instance → no type argument), so it declares its own.

### C. Bounds

- `<T extends Number>` — T is Number or subclass (works for classes *and* interfaces; always the keyword `extends`).
- `<T extends Comparable<T>>` — the sortable bound.
- Multiple bounds: `<T extends Shape & Comparable<T>>`.

### D. Type erasure — what the compiler actually does

Generics exist **only at compile time**. After type-checking, the compiler *erases* `T` to its bound (`Object` by default) and inserts casts at use sites. Consequences you must know:

```java
T x = new T();                    // ✗ can't instantiate a type parameter
T[] arr = new T[10];              // ✗ can't create generic arrays
T[] arr = (T[]) new Object[10];   // ✓ the idiom (unchecked warning; @SuppressWarnings("unchecked"))
if (obj instanceof T)             // ✗ T doesn't exist at run time
if (list instanceof ArrayList<String>)   // ✗ same reason; ArrayList<?> is OK
static T shared;                  // ✗ static members can't use the class's T
List<int>                         // ✗ primitives aren't Objects → use Integer
new ArrayList<String>().getClass() == new ArrayList<Integer>().getClass()   // true — one class at run time
```

Also explains why `ArrayList<Circle>` isn't an `ArrayList<Shape>` (no run-time info to make it safe) and why wildcards exist.

### E. Stack ADT — LIFO

Operations: `push(x)`, `pop()` (remove & return top), `peek()` (return top), `isEmpty()`, `size()`. Empty `pop`/`peek` → throw `NoSuchElementException` (or `EmptyStackException`).

**Array-backed** — top is the end of the array:
```java
public class ArrayStack<T> {
    private T[] data = (T[]) new Object[10];
    private int size;
    public void push(T x) { if (size == data.length) resize(); data[size++] = x; }   // O(1) amortized
    public T pop() {
        if (isEmpty()) throw new NoSuchElementException();
        T out = data[--size]; data[size] = null; return out;                         // null out to avoid leaks
    }
    public T peek() { if (isEmpty()) throw new NoSuchElementException(); return data[size - 1]; }
    public boolean isEmpty() { return size == 0; }
}
```

**Linked** — top is the head (both ends O(1) guaranteed):
```java
public void push(T x) { head = new Node(x, head); size++; }
public T pop() { T out = head.data; head = head.next; size--; return out; }
```

Uses: undo history, method call stack (recursion!), balanced-parentheses check, expression evaluation, DFS.

Balanced brackets sketch: push openers; on a closer, pop and check it matches; at end, stack must be empty.

## 3. Self-check (~6 min)

1. Fix the signature: `public static T first(T[] a) { return a[0]; }`
   <details><summary>Answer</summary><code>public static &lt;T&gt; T first(T[] a)</code> — a generic method must declare its own type parameter.</details>
2. Why is `T[] a = new T[n];` illegal, and what do you write instead?
   <details><summary>Answer</summary>Type erasure — no <code>T</code> at run time to allocate. <code>(T[]) new Object[n]</code> with <code>@SuppressWarnings("unchecked")</code>.</details>
3. Sequence: `push(1) push(2) pop() push(3) peek() pop() pop()` — what's returned by each pop/peek, and what happens on a further `pop()`?
   <details><summary>Answer</summary>pop→2, peek→3, pop→3, pop→1; next pop throws (empty).</details>
4. In the linked stack, why push/pop at the head rather than the tail?
   <details><summary>Answer</summary>Head operations are O(1); the tail of a singly linked list requires an O(n) walk (or a tail pointer, and even then pop would need the previous node).</details>
5. `Box<Integer> a; Box<String> b; a.getClass() == b.getClass()` → ?
   <details><summary>Answer</summary><code>true</code> — erasure leaves a single <code>Box</code> class.</details>
6. Can `class Counter<T> { static int count; }` exist? Can it be `static T last;`?
   <details><summary>Answer</summary>Yes; no — statics can't reference the instance type parameter.</details>
