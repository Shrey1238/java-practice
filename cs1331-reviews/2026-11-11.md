## 2. Today's concepts

### A. Set ADT

A collection with **no duplicates** and (in the abstract) **no order**.

| op | meaning |
|---|---|
| `boolean add(x)` | add if absent; returns `false` if already present (no exception!) |
| `boolean remove(x)` | remove if present |
| `boolean contains(x)` | membership |
| `size()`, `isEmpty()`, `clear()` | |
| set algebra (maybe) | union `addAll`, intersection `retainAll`, difference `removeAll` |

"Duplicate" is decided by **`equals`** (and `hashCode` for hash-based sets — the Oct 9 contract finally pays off).

Simple implementations you might sketch in class:
- **Array/ArrayList-backed set**: `add` = `contains` check O(n) then append. `contains` O(n).
- **Linked set**: same complexities.
- **Hash set** (Nov 18): `add`/`contains` ≈ O(1) using `hashCode` to pick a bucket, `equals` within the bucket.

```java
public class ArraySet<T> implements Iterable<T> {
    private T[] data = (T[]) new Object[8];
    private int size;

    public boolean contains(T x) {
        for (int i = 0; i < size; i++) if (data[i].equals(x)) return true;
        return false;
    }
    public boolean add(T x) {
        if (x == null) throw new IllegalArgumentException();
        if (contains(x)) return false;
        if (size == data.length) data = Arrays.copyOf(data, size * 2);
        data[size++] = x;
        return true;
    }
    public boolean remove(T x) {
        for (int i = 0; i < size; i++) {
            if (data[i].equals(x)) {
                data[i] = data[--size];          // unordered → swap last into the hole, O(1)
                data[size] = null;
                return true;
            }
        }
        return false;
    }
```

### B. Writing an `Iterator` — named inner class

Friday you saw the anonymous-class version. The named **inner class** version is what HWs usually ask for; note it can read the outer object's fields directly (`data`, `size`) because it's non-static.

```java
    @Override
    public Iterator<T> iterator() { return new ArraySetIterator(); }

    private class ArraySetIterator implements Iterator<T> {
        private int index = 0;                                 // iteration state lives HERE, not in the set

        @Override public boolean hasNext() { return index < size; }

        @Override public T next() {
            if (!hasNext()) throw new NoSuchElementException();
            return data[index++];
        }
        // remove() has a default implementation that throws UnsupportedOperationException — fine to leave it
    }
}
```

Linked version: state is `private Node cur = head;` → `hasNext: cur != null`; `next: T out = cur.data; cur = cur.next; return out;`.

Design rules:
1. Iterator holds its **own cursor** so two loops over the same collection don't interfere.
2. `next()` must **throw** when exhausted — don't return `null`.
3. `hasNext()` must be **side-effect-free** (calling it twice shouldn't skip elements).
4. Modifying the collection mid-iteration → undefined / `ConcurrentModificationException` in library classes. HW iterators typically don't need to detect this.
5. Static nested class (`private static class`) can't see outer instance fields — you'd pass what you need into its constructor. Either is acceptable if it works; inner (non-static) is simpler here.

### C. Iterator vs for-each vs index — Big-O reminder

| traversal | ArrayList | LinkedList |
|---|---|---|
| `for (i < size) get(i)` | O(n) | **O(n²)** |
| for-each / iterator | O(n) | O(n) |

1. `set.add("a"); set.add("a"); set.size()` → ? What did the second `add` return?
   <details><summary>Answer</summary>1; <code>false</code>.</details>
2. You forget to override `hashCode` in `Point` but override `equals`. `HashSet<Point>` behavior?
   <details><summary>Answer</summary>Two equal points usually land in different buckets → both are added; <code>contains</code> may return false for an equal point. (For an ArraySet using only <code>equals</code> it would work — which is why the bug hides.)</details>
3. Output?
   ```java
   Iterator<Integer> it = List.of(1, 2, 3).iterator();
   it.hasNext(); it.hasNext();
   System.out.println(it.next() + " " + it.next());
   ```
   <details><summary>Answer</summary><code>1 2</code> — <code>hasNext</code> doesn't advance.</details>
4. Why can a non-static inner iterator class access `data` and `size` without a reference?
   <details><summary>Answer</summary>An inner (non-static) class instance is bound to the enclosing instance and can use its fields directly.</details>
5. In `ArraySet.remove`, why is "move the last element into the hole" acceptable when it wouldn't be for a List?
   <details><summary>Answer</summary>Sets are unordered, so element positions don't matter; a List must preserve order (shift instead).</details>
