## 1. Recap — the ADT ideas this builds on

- ADT = interface (what), class = implementation (how); code against the interface: `List<String> xs = new ArrayList<>();`
- Stack = LIFO (`push/pop/peek`); Set = no duplicates via `equals`/`hashCode`; Iterator for traversal.
- Big-O: array-backed random access O(1), front insert O(n); linked front ops O(1), index O(n).

## 2. Today's concepts

### A. The Java Collections Framework map

```
Iterable
 └─ Collection
     ├─ List      → ArrayList, LinkedList
     ├─ Queue     → LinkedList, ArrayDeque, PriorityQueue
     │    └─ Deque → ArrayDeque, LinkedList
     └─ Set       → HashSet, LinkedHashSet, TreeSet
Map (separate hierarchy) → HashMap, LinkedHashMap, TreeMap
```

"Polymorphism with ADTs": declare the **interface** type, instantiate the **implementation**. Swapping `ArrayList` for `LinkedList` changes performance, not code.

### B. `Stack` (LIFO) — 11.13

```java
Deque<Integer> stack = new ArrayDeque<>();     // preferred modern stack
stack.push(1); stack.push(2);
stack.peek();     // 2
stack.pop();      // 2
stack.isEmpty();

Stack<Integer> legacy = new Stack<>();          // java.util.Stack — the textbook's; same push/pop/peek, empty()
```
`java.util.Stack` extends `Vector` (a List), so it leaks index access — that's why `Deque` is preferred. Know both; use whatever the HW says.

### C. `Queue` (FIFO) — and LIFO vs FIFO

```java
Queue<String> q = new LinkedList<>();           // or new ArrayDeque<>()
q.add("a"); q.offer("b");                       // enqueue at the back
q.peek();       // "a"  (front, no removal; null if empty)
q.poll();       // "a"  (dequeue; null if empty)
q.remove();     // like poll but throws NoSuchElementException if empty
```

| | Stack (LIFO) | Queue (FIFO) |
|---|---|---|
| insert | `push` (top) | `add`/`offer` (back) |
| remove | `pop` (top) | `poll`/`remove` (front) |
| look | `peek` | `peek` |
| analogy | plates | checkout line |
| uses | undo, call stack, DFS, brackets | scheduling, BFS, buffering |

`Deque` (double-ended) does both: `addFirst/addLast/removeFirst/removeLast/peekFirst/peekLast`. `push`=`addFirst`, `pop`=`removeFirst`.

`PriorityQueue<E>`: `poll()` returns the **smallest** by `compareTo` (or a `Comparator`) — not FIFO.

### D. `Set<E>`

```java
Set<String> seen = new HashSet<>();
seen.add("x");           // true
seen.add("x");           // false — duplicate
seen.contains("x");      // ~O(1)
seen.remove("x");
```

| impl | order | `add`/`contains` | needs |
|---|---|---|---|
| `HashSet` | none | O(1) avg | `hashCode` + `equals` |
| `LinkedHashSet` | insertion | O(1) avg | same |
| `TreeSet` | sorted | O(log n) | `Comparable` (or `Comparator`) |

Dedupe a list: `new ArrayList<>(new LinkedHashSet<>(list))`.

### E. `Map<K, V>`

Key → value; keys unique; each key maps to one value.

```java
Map<String, Integer> counts = new HashMap<>();
counts.put("a", 1);                     // insert/replace; returns previous value or null
counts.get("a");                        // 1;   get("zzz") → null (not an exception!)
counts.getOrDefault("b", 0);            // 0
counts.containsKey("a"); counts.containsValue(1);
counts.remove("a");
counts.size();

// word-count idiom
for (String w : words) counts.put(w, counts.getOrDefault(w, 0) + 1);
// or: counts.merge(w, 1, Integer::sum);

// iteration
for (String k : counts.keySet()) { ... }
for (Integer v : counts.values()) { ... }
for (Map.Entry<String, Integer> e : counts.entrySet()) { e.getKey(); e.getValue(); }
```

`HashMap` (unordered, O(1)) · `LinkedHashMap` (insertion order) · `TreeMap` (sorted keys, O(log n)). Keys must have correct `hashCode`/`equals` (or be `Comparable` for `TreeMap`). Mutating a key after insertion breaks the map.

### F. Utility classes

`Collections.sort(list)`, `Collections.reverse`, `Collections.max`, `Collections.unmodifiableList`; `List.of(...)`/`Set.of(...)`/`Map.of(...)` create **immutable** collections (`add` throws `UnsupportedOperationException`).
