## 2. Today's concepts — what Spring Boot is

### A. The big picture

- **Spring** = a Java framework for building applications (especially web/back-end). Its core trick: *you* write plain classes; *Spring* creates and wires them together.
- **Spring Boot** = Spring with sensible defaults + an embedded web server (Tomcat) so a web app runs with `main()` — no separate server install, minimal config.
- Why it's in CS 1331: it's the payoff for everything OOP — interfaces, polymorphism, annotations, collections — in a real-world shape.

### B. Vocabulary you'll hear in the demo

| term | meaning |
|---|---|
| **HTTP request/response** | browser/client sends `GET /todos`; server replies with status (200 OK, 404) + body (HTML or JSON) |
| **GET / POST / PUT / DELETE** | read / create / update / delete — the verbs of REST |
| **REST API** | URLs identify resources (`/todos`, `/todos/3`), verbs act on them, usually JSON in/out |
| **JSON** | `{"id": 3, "title": "study", "done": false}` — Java objects auto-converted (Jackson) |
| **endpoint** | a URL+verb handled by one method |
| **controller** | class whose methods handle requests |
| **service** | class holding business logic |
| **repository** | class/interface that stores & retrieves data |
| **annotation** | `@Something` metadata on a class/method/field that Spring reads — like `@Override`, but Spring acts on it |
| **Maven / Gradle** | build tools; `pom.xml` lists dependencies (you already use `./mvnw`) |
| **localhost:8080** | default address of the embedded server |

### C. Anatomy of the smallest Spring Boot app

```java
@SpringBootApplication                                  // turns on auto-config + component scanning
public class TodoApplication {
    public static void main(String[] args) {
        SpringApplication.run(TodoApplication.class, args);   // starts the server; never "returns" while running
    }
}
```

```java
@RestController                                         // "my methods return data (JSON), not HTML pages"
@RequestMapping("/todos")                               // base URL for every method here
public class TodoController {
    private final List<Todo> todos = new ArrayList<>();  // demo storage (a real app uses a repository)

    @GetMapping                                          // GET /todos
    public List<Todo> all() { return todos; }

    @GetMapping("/{id}")                                 // GET /todos/3
    public Todo one(@PathVariable int id) { return todos.get(id); }

    @PostMapping                                         // POST /todos with a JSON body
    public Todo create(@RequestBody Todo t) { todos.add(t); return t; }

    @DeleteMapping("/{id}")                              // DELETE /todos/3
    public void delete(@PathVariable int id) { todos.remove(id); }
}
```

```java
public class Todo {                                     // a plain "POJO" — needs getters/setters (or a record) for JSON
    private int id; private String title; private boolean done;
    public Todo() {}                                     // no-arg constructor for deserialization
    // getters & setters …
}
```

Or as a Java `record`: `public record Todo(int id, String title, boolean done) {}` — immutable, auto `equals/hashCode/toString`.

### D. What to watch for during the demo

1. Project layout: `src/main/java/...Application.java`, controllers in a subpackage, `src/main/resources/application.properties`.
2. How a URL maps to a method (`@GetMapping("/{id}")` + `@PathVariable`).
3. How a Java object becomes JSON and back (`@RequestBody`, return values).
4. Testing endpoints with the browser (GET only), `curl`, or Postman.
5. The console log when the app starts — "Tomcat started on port 8080".

### E. Connecting to CS 1331 concepts

- Annotations are metadata processed by a framework — same mechanism as `@Override`/`@SuppressWarnings`, different consumer.
- Controllers/services/repositories are just **classes with single responsibilities** — the class-design lessons from September.
- Interfaces + polymorphism let Spring swap implementations (Monday: dependency injection is exactly this).
- Collections (`List<Todo>`, `Map<Integer, Todo>`) are the in-memory storage.

## 3. Self-check (~4 min)

1. Which HTTP verb + URL would "mark todo 7 as done" most naturally use?
   <details><summary>Answer</summary><code>PUT /todos/7</code> (or <code>PATCH</code>) with a body containing <code>done: true</code>.</details>
2. What does `@RestController` add over `@Controller`?
   <details><summary>Answer</summary>Method return values are written directly to the response body (JSON) instead of being treated as view/template names.</details>
3. Why does `Todo` need a no-arg constructor and getters/setters?
   <details><summary>Answer</summary>The JSON library instantiates it reflectively and reads/writes properties through accessors.</details>
4. What annotation binds the `3` in `/todos/3` to a method parameter?
   <details><summary>Answer</summary><code>@PathVariable</code>.</details>
5. Where's the "main" of a Spring Boot app, and what does `SpringApplication.run` do?
   <details><summary>Answer</summary>The <code>@SpringBootApplication</code> class; it boots the container, scans for components, and starts the embedded server.</details>
